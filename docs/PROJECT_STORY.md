# Pawlaroid 产品故事与设计思考

> 一份写给「想了解这个项目为什么长这样」的人的设计笔记。

---

## 1. 起点：一张照片，想被好好收藏

我们给宠物拍过无数张照片，但它们大多躺在相册里、聊天记录里，慢慢被刷走。
Pawlaroid 想做一件很小的事：**让某一张普通的抓拍，变成一张值得被捧在手里的拍立得。**

拍立得的魅力不在“清晰”，而在“仪式”——你按下快门，它要等一会儿才显影；
你写下日期和一句话，它就成了那一天的标本。Pawlaroid 把这套仪式搬到了屏幕上。

---

## 2. 三个空间，三种回忆姿态

产品没有做成“一个相册页”，而是三个气质不同的空间：

- **首页（此刻）**：最轻的入口，一张照片 + 一次咔嚓。重点是“现在就拍”。
- **时光机（回望）**：按日期倒序、按天分组的成长长图。它回答的是
  “它什么时候长大的”。导出成一张长图，像翻一本手帐。
- **展示墙（陈列）**：可自由拖拽、旋转、钉上图钉的回忆墙。它回答的是
  “哪些瞬间我想一直看着”。

三者共享同一份数据（`PawMemory`），但呈现姿态完全不同 —— 这是刻意的：
同一种记忆，值得有不同的打开方式。

---

## 3. “冲洗”是一种交互，不是一句文案

核心交互被命名为**冲洗（Develop）**，而不是“保存”或“生成”。

一次冲洗包含：快门闪光 → 元素聚合落位 → 相纸从模糊到清晰（`blur → clear`）
→ 完成提示。它把一次技术动作（Canvas 合成 + `toDataURL`）包装成有呼吸感的仪式。
我们相信：工具感越弱，情感越容易落进去。

---

## 4. 视觉：暖、手帐、微倾斜

- 底色用暖米白（`#FFFBF2`）模拟胶片纸。
- 留言用手写体（Caveat / Long Cang / Ma Shan Zheng / ZCOOL KuaiLe），
  并做了 `document.fonts.load` 预热，避免长图导出时字体未下载导致静默回退。
- 拍立得、便签、和纸胶带都做了**微倾斜**，避免“对齐到像素”的工业感。
- 分隔条、波浪线、小爪印等手帐元素，用来分隔“日期 / 留言 / 照片”的信息层级。

克制是关键：装饰服务于信息，不是为了热闹。

---

## 5. 工程取舍：零依赖，但认真

- **零框架、零构建**：整个应用是原生 HTML/CSS/JS，双击或起个静态服务器就能跑。
  这降低了“想看看效果”的门槛，也让代码本身成为可阅读的样本。
- **双源资源加载**：`file://` 下浏览器禁止 `fetch` 本地文件，所以用 `<script>`
  注入 `window.PAW_*` 数组兜底；`http(s)` 下则 `fetch` 同名 `.json` 优先。
  两者内容必须同步 —— 这是这个项目踩过最多的坑，也是 `paperStyles.js` /
  `wall.js` 里反复强调的约束。
- **资产路由集中化**：所有图片路径经 `js/assetConfig.js` 的 `resolve()` 出口，
  避免硬编码散落、避免 `file://` 与 `http` 两种环境不一致。
- **Canvas 污染**：`file://` 下用本地图片绘 Canvas 会污染画布，导出时
  `toDataURL()` 抛 `SecurityError`。本地完整副本用内联资源规避；公开仓库走
  `http` 同源相对路径，天然不污染。

---

## 6. 资产策略：展示能力，也保护创作者

公开仓库需要同时做两件事，且不能互相伤害：

1. **展示完整前端能力** —— 页面结构、组件逻辑、合成、展示墙、时光机、导出都要能跑。
2. **保护原创视觉资产** —— 不公开完整相框库 / 贴纸库 / 高清素材。

解法不是“加密”，而是**物理隔离 + 代表性子集**：

- 仓库内置**降采样、有代表性的素材子集**（3 相框 + 3 贴纸 + 签名素材），
  足以演示全部功能与视觉风格。
- 完整原创资产保存在仓库外的独立目录，永不进 `git`。
- 相纸 / 贴纸通过 `frames/`、`stickers/` 的配置文件驱动，任何人都能按相同结构
  替换为自己的素材 —— 项目因此既是作品，也是模板。

---

## 7. 一句话总结

Pawlaroid 不是“一个导出图片的工具”，而是一台**把和毛孩子相处的时光，
冲洗成可以珍藏的拍立得**的小机器。技术服务于这个温柔的隐喻，而不是反过来。
